# Checkstyle gate 129856 - Bruno Frasco

## Regra escolhida
Convenção de nomes de **classes e interfaces** (regra `TypeName` do Checkstyle), com o padrão por defeito `^[A-Z][a-zA-Z0-9]*$`: o nome começa por maiúscula e não tem sublinhados.

## Ficheiros
- Configuração: `checkstyle-129856.xml` (raiz do repositório), só com a regra `TypeName`.
- Workflow: `.github/workflows/checkstyle-129856.yaml`, que usa a action `dbelyaev/action-checkstyle@v3` (Checkstyle 13.10.0), corre em pull request e falha com `fail_level: error`.
- O check `checkstyle-129856` está configurado como obrigatório no ramo `master`, por isso um pull request com o gate vermelho não pode ser integrado.

## Execuções (pull request #45)

`src/main/java/battleship/battle_ship.java:3:14: Name 'battle_ship' must match pattern '^[A-Z][a-zA-Z0-9]*$'`.
O botão de merge do PR ficou bloqueado enquanto o check estava vermelho. Depois de corrigir o nome, o check passou. O PR #45 foi fechado sem merge, porque a classe era só um teste.

## O que o Checkstyle não consegue verificar
O Checkstyle só valida a **forma** do nome, e não o seu significado. Nomes como `Xyz1` ou `Aaa` cumprem o padrão e continuam a ser maus nomes, porque não dizem o que a classe faz. Também não verifica se o nome está no idioma combinado pelo grupo, nem se a classe tem responsabilidades coerentes com o nome que tem.
